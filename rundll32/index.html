Deploy Windows using DISM and provisioning packages

📅 Published: May 2025 📄 Applies to: Windows 11, Windows Server 2025, Windows 10 ✍️ Windows Deployment Engineering Team

This article provides technical guidance for IT pros and system administrators to deploy, capture, and service Windows images using the Deployment Imaging Servicing and Management (DISM) tool. DISM is built into Windows and can be used to prepare WinPE, apply customizations, and manage features, drivers, and packages offline or online.

Understanding DISM and image servicing

DISM is a command-line tool that mounts a Windows image (.wim, .vhdx, or .ffu) for offline servicing. It can add or remove drivers, enable or disable Windows features, apply security updates, and configure international settings. DISM is the primary method to maintain Windows images before deployment.

# Mount an image to service it offline
DISM /Mount-Image /ImageFile:"D:\sources\install.wim" /Index:1 /MountDir:"C:\mount\windows"

# Add a driver package
DISM /Image:"C:\mount\windows" /Add-Driver /Driver:"C:\Drivers\Network" /Recurse

# Enable .NET Framework 3.5
DISM /Image:"C:\mount\windows" /Enable-Feature /FeatureName:NetFx3 /All /LimitAccess /Source:"D:\sources\sxs"

# Commit changes and unmount
DISM /Unmount-Image /MountDir:"C:\mount\windows" /Commit

Enterprise environments often combine DISM with Windows Configuration Designer to create provisioning packages (.ppkg) that apply settings during out-of-box experience (OOBE). Starting in Windows 11, DISM supports new parameters for managing Windows Update policies and dynamic updates.

💡 Important: Always validate the image index using DISM /Get-ImageInfo before mounting. Running DISM on a corrupted image may result in deployment failures.

Windows provisioning with answer files (unattend.xml)

While DISM handles offline servicing, Windows Setup uses answer files (unattend.xml) to automate installation. The Windows System Image Manager (Windows SIM) allows you to create answer files that configure disk partitioning, product keys, locale settings, and driver injection. A typical workflow includes:

  • Creating a reference image (audit mode) with required apps and customizations.
  • Generalizing the image using sysprep /generalize /oobe /shutdown.
  • Capturing the image using DISM: DISM /Capture-Image /ImageFile:"D:\deploy.wim" /CaptureDir:C:\ /Name:"CustomWin11".
  • Applying the image to target devices using WinPE and DISM /Apply-Image.

For large-scale deployments, Microsoft recommends using Microsoft Deployment Toolkit (MDT) or Microsoft Configuration Manager (MCM) that leverage DISM under the hood. Windows Autopilot provides a cloud-first approach for zero-touch deployment, but still relies on provisioning packages and modern driver management.

Driver management and servicing stack updates

In-box drivers are critical for hardware compatibility. Using DISM, you can add both inbox and third-party drivers to offline images. The command DISM /Add-Driver supports .inf files and recursively scans folders. To remove outdated drivers, use DISM /Remove-Driver.

TaskDISM Command Example
List drivers in mounted imageDISM /Image:"C:\mount" /Get-Drivers
Remove a specific driverDISM /Image:"C:\mount" /Remove-Driver /Driver:oem1.inf
Export drivers from running OSDISM /Online /Export-Driver /Destination:"C:\DriverBackup"

Servicing stack updates (SSU) ensure that the component-based servicing infrastructure is reliable. Microsoft regularly publishes SSUs via Windows Update, and you can also install them offline: DISM /Add-Package /Image:"C:\mount" /PackagePath:"windows10.0-kb5021234-x64.msu".

Best practices for Windows image lifecycle

To maintain secure and up-to-date deployments, follow these recommendations:

  • Always use the latest Windows ADK (Assessment and Deployment Kit) version for servicing.
  • Clean up superseded components using DISM /Cleanup-Image /StartComponentCleanup to reduce image size.
  • Use /ScratchDir to avoid temp space issues when mounting large images.
  • Apply cumulative updates offline before deploying to reduce patching time on end devices.
  • Validate images with Windows Hardware Lab Kit (HLK) for driver signing.
📌 Note: Starting with Windows 11 version 24H2, DISM includes native support for managing Windows Recovery Environment (WinRE) and dynamic update packages. Use DISM /Get-ImageHealth to verify image integrity.

Automating deployments using scripts and configuration files

PowerShell and DISM can be combined to create fully automated deployment pipelines. Example script below shows a simple routine to apply a clean image to a new drive:

# Apply Windows image to C: drive
$wimPath = "E:\Images\win11_enterprise.wim"
$index = 2
$applyDir = "C:\"

# Apply image
Expand-WindowsImage -ImagePath $wimPath -Index $index -ApplyPath $applyDir

# Add boot loader
bcdboot C:\Windows /s S: /f UEFI

# Use DISM to add language pack
Add-WindowsPackage -Path $applyDir -PackagePath "D:\langpacks\en-us.cab"

For organizations that use Windows Update for Business, you can also use DISM to manage Feature Update deferrals and quality update exposure controls. For more in-depth details, see the official Windows Deployment and Imaging guide (reference).

Troubleshooting common deployment errors

Error 0x80070070 indicates insufficient disk space. Ensure that the scratch directory and destination drive have adequate free space (at least 15GB). Error 0x800F0954 typically means DISM cannot reach required source files; specify /Source and /LimitAccess appropriately. Use DISM /Cleanup-Wim to clean up stale mount points.

If mounted images become corrupted, run DISM /Cleanup-Mountpoints and restart the servicing environment. Always log DISM operations: DISM /LogPath:C:\DISM.log.
